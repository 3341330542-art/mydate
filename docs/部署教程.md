# 部署教程 · 从零到公网链接和二维码

这份教程假设你**完全没有部署过网站**，跟着一步一步做就行。
全程用免费服务，不需要买服务器、不需要备案、不需要绑域名。

**预计用时 25 分钟**，其中大部分时间是在等 Supabase 建项目。

---

## 总览

```
① 注册三个免费账号            GitHub / Supabase / Vercel          （5 分钟）
        ↓
② 本地把项目跑起来            npm install → npm run dev            （5 分钟）
        ↓
③ 建数据库                    Supabase 建项目 + 执行一段 SQL       （5 分钟）
        ↓
④ 填环境变量                  把 URL 和 key 写进 .env.local         （1 分钟）
        ↓
⑤ 代码推到 GitHub             git push                             （3 分钟）
        ↓
⑥ 部署到 Vercel               导入仓库 + 填环境变量 → Deploy        （5 分钟）
        ↓
⑦ 拿到公网链接                 https://xxx.vercel.app
        ↓
⑧ 生成二维码发给女朋友         截图 / 命令行 / 在线工具都行
```

做完之后你会得到：**一个公网链接 + 一个二维码**。她扫一下就能进入你们两个人的空间。

### 0.1 需要注册的账号（都是免费的）

| 服务 | 用途 | 地址 |
| --- | --- | --- |
| **GitHub** | 存放代码 | https://github.com/signup |
| **Supabase** | 云端数据库（存约会数据） | https://supabase.com/dashboard |

注册 Vercel 和 Supabase 时都可以**直接用 GitHub 账号登录**，会快很多，建议先注册 GitHub。

需要 **Node.js 20.9 或更高版本**。检查一下：

```bash
node -v
```

如果没装或者版本太低，去 https://nodejs.org 下载 LTS 版本安装。

还需要 **Git**：


## 第 1 步：本地把项目跑起来

先确认项目在本机能跑，再去折腾云端，这样出问题好排查。

### 1.1 安装依赖

在项目根目录（也就是有 `package.json` 的那个文件夹）打开终端：

```bash
npm install
```

第一次会下载一些包，等一两分钟。

### 1.2 先用演示模式看一眼

项目自带**演示模式**，不连数据库也能看到完整界面。

把 `.env.example` 复制一份叫 `.env.local`：

```bash
# macOS / Linux
cp .env.example .env.local

# Windows PowerShell
copy .env.example .env.local
```

打开 `.env.local`，加上这一行：

```env
NEXT_PUBLIC_DEMO_MODE=1
```

然后启动：

```bash
npm run dev
```

浏览器打开 **http://localhost:3000** 就能看到界面了。

> 演示模式的数据是假的，刷新会重置。这一步只是为了确认环境没问题，
> 顺便看看样式喜不喜欢。**正式使用必须配置数据库**，否则数据不会保存。

看到界面之后，按 `Ctrl + C` 停掉服务，继续往下。

## 第 2 步：创建并配置数据库

这一步是**最关键的一步**，做完之后数据就能永久保存了。

### 2.1 新建 Supabase 项目

1. 打开 https://supabase.com/dashboard 并登录
2. 点绿色的 **New project** 按钮
3. 填写：
   - **Organization**：随便，默认就行
   - **Name**：比如 `couple-dates`
   - **Database Password**：点 **Generate a password** 生成一个，然后**复制保存到安全的地方**
     （这个密码本项目用不到，但以后要直连数据库会需要）
   - **Region**：选离你最近的，国内用户一般选 `Southeast Asia (Singapore)` 或 `Northeast Asia (Tokyo)`
   - **Pricing Plan**：保持 **Free**
4. 点 **Create new project**

然后**等 1~2 分钟**，等它把数据库准备好。页面上会有进度提示。

### 2.2 执行初始化脚本（建表）

项目里已经写好了完整的数据库脚本，你只需要粘贴执行一次。

1. 在 Supabase 项目页面左侧栏点 **SQL Editor**（图标是一个 `>_`）
2. 点 **New query**
3. 打开项目里的 **`supabase/migrations/0001_init.sql`**，**把整个文件的内容全部复制**，
   粘贴到编辑器里
4. 点右下角的 **Run**（或者按 `Ctrl + Enter`）

看到 **"Success. No rows returned"** 就说明成功了。

> 这个脚本可以**重复执行**，不会报错也不会清空已有数据。
> 以后想重新跑一遍也没问题。

它一次性帮你做好了这些事：

- 建了 5 张表：`profiles`（用户资料）、`couples`（情侣空间）、`couple_members`（成员）、`dates`（约会）、`ideas`（灵感清单）
- 写好了**行级安全策略**：每个人只能看到自己所在空间的数据
- 写好了加入空间的逻辑（邀请码、最多 2 人、一人只能在一个空间）
- 打开了**实时同步**，两个人的改动会互相推送

### 2.3 确认表建好了

1. 左侧栏点 **Table Editor**
2. 应该能看到 `couples`、`couple_members`、`dates`、`ideas`、`profiles` 五张表

看到就对了。

### 2.4 关掉邮箱确认（强烈建议）

Supabase 默认要求注册后去邮箱点确认链接才能登录。对你女朋友来说这一步很麻烦，
建议关掉，注册完直接就能进：

1. 左侧栏点 **Authentication**
2. 点 **Sign In / Providers**（有些版本叫 **Providers**）
3. 找到 **Email**，展开
4. 把 **Confirm email** 关掉（变成灰色 / 关闭状态）
5. 点 **Save**

> 同时确认 **Allow new users to sign up** 是**开着**的，不然她注册不了。
>
> 如果你更在意安全、愿意让她多点一次邮箱链接，也可以保持开启 ——
> 程序对这种情况做了处理，会提示她「去邮箱确认一下吧」。

### 2.5 设置 Site URL（部署完之后再做也行）

1. **Authentication** → **URL Configuration**
2. **Site URL** 填你部署后的地址，比如 `https://our-dates.vercel.app`
3. **Save**

这一步对「邮箱 + 密码」登录不是必须的，但设上没坏处。
等你第 6 步拿到正式链接之后回来补也行。

## 第 3 步：配置环境变量

### 3.1 找到两个值

在 Supabase 项目页面：

1. 左侧栏最下面点 **Project Settings**（齿轮图标）
2. 点 **Data API**（旧版叫 **API**）
3. 找到两个东西：

| 名字 | 长什么样 | 在哪 |
| --- | --- | --- |
| **Project URL** | `https://abcdefghijk.supabase.co` | Data API 页面顶部 |
| **anon / public key** | 一长串 `eyJhbGciOi...` 开头的字符串 | 同一页的 **API Keys** 区域，标着 `anon` `public` |

> **新版控制台**里这把钥匙可能叫 **Publishable key**（以 `sb_publishable_` 开头），
> 用法完全一样，复制它就行。

⚠️ **千万不要复制 `service_role` / `Secret key`！** 那把钥匙能绕过所有权限控制，
只能放在服务器上，绝对不能进前端代码。本项目只需要 `anon` / `publishable`。

### 3.2 写进 `.env.local`

打开项目根目录的 `.env.local`，改成这样（值换成你自己的）：

```env
NEXT_PUBLIC_SUPABASE_URL=https://abcdefghijk.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpc3MiOiJzdXBhYmFzZSI...

# 本地开发时先不填，等部署完再回来改成正式地址
NEXT_PUBLIC_SITE_URL=
```

**把 `NEXT_PUBLIC_DEMO_MODE` 那一行删掉**（或者改成 `0`）。

> 小提示：即使你忘了删演示模式那行，只要填了上面两个值，程序也会优先连真实数据库。

### 3.3 验证一下

```bash
npm run dev
```

打开 http://localhost:3000 ，这次应该看到**登录 / 注册**页面，而不是演示模式的首页。

注册一个账号（用你自己的邮箱），然后会进入「建立你们的小天地」页面，填个空间名字创建。
创建成功后应该能看到首页，并且**刷新页面数据还在** —— 说明数据库通了 ✅

## 第 4 步：把代码传到 GitHub

如果你的项目还不是一个 git 仓库：

```bash
git init
git add .
git commit -m "情侣约会空间：初始版本"
```

> `git add .` 之前可以放心，`.gitignore` 已经把 `.env.local` 排除了，
> 你的密钥不会被提交上去。想确认一下可以跑 `git status`，看看列表里有没有 `.env.local`
> —— **不应该有**。

然后在 GitHub 上：

1. 点右上角 **+** → **New repository**
2. **Repository name** 填 `couple-dates`（随便）
3. 选 **Private**（私有，推荐）或者 Public 都行
4. **不要**勾选 "Add a README file"（我们已经有 README 了）
5. 点 **Create repository**

创建后 GitHub 会给你两行命令，在你的项目目录里执行（记得把 `你的用户名` 换掉）：

```bash
git remote add origin https://github.com/你的用户名/couple-dates.git
git branch -M main
git push -u origin main
```

推送成功后在 GitHub 页面上就能看到你的代码了。

## 第 5 步：部署到 Vercel

1. 打开 https://vercel.com 并用 **GitHub 账号登录**
2. 进入控制台后点 **Add New…** → **Project**
3. 在 **Import Git Repository** 列表里找到刚才那个仓库，点 **Import**
   - 如果没看到，点 **Adjust GitHub App Permissions** 授权一下
4. **Configure Project** 页面：

   - **Framework Preset**：应该自动识别为 **Next.js**，不用改
   - **Root Directory**：保持默认 `./`
   - **Build and Output Settings**：全部保持默认
   - **Environment Variables**：⚠️ **这里一定要填**，展开它，添加三行：

     | Name | Value |
     | --- | --- |
     | `NEXT_PUBLIC_SUPABASE_URL` | 你的 Project URL |
     | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 你的 anon / publishable key |
     | `NEXT_PUBLIC_SITE_URL` | 先随便填 `https://example.com`，等拿到正式地址再改（见第 5.3 步） |

5. 点 **Deploy**，等 1~2 分钟

部署完成后，Vercel 会给你一个地址，形如：

```
https://couple-dates-xxxx.vercel.app
```

🎉 **这就是你的公网链接。**

> **关于 `NEXT_PUBLIC_SITE_URL` 的说明**：它决定了邀请链接和二维码里用的域名。
> 留空的话程序会自动用浏览器当前地址，效果其实也一样。
> 想填的话，建议先把前两个变量填上部署一次，拿到正式域名后再回来补第三个。

### 5.3 回填正式的 SITE_URL（建议）

1. 在 Vercel 项目页面点 **Settings** → **Environment Variables**
2. 把 `NEXT_PUBLIC_SITE_URL` 的值改成你的正式地址，比如 `https://couple-dates-xxxx.vercel.app`
3. 回到 **Deployments** 标签，最新那条右边点 **⋯** → **Redeploy**

> ⚠️ `NEXT_PUBLIC_` 开头的变量是在**打包时**写进代码里的，
> 所以**改完环境变量必须重新部署（Redeploy）才会生效**。只改不重新部署没用。

## 第 7 步：生成二维码

有四种方式，**推荐第一种**，最简单。

### 方法 A：直接用小程序里的二维码（推荐）

1. 打开你的 `https://xxx.vercel.app`
2. 底部切到 **我的**
3. 往下找到 **邀请另一半**，那里已经有一张二维码了
4. **直接截图**，发给女朋友

二维码里装的就是你的邀请链接，她扫一下就进去了。

### 方法 B：命令行生成 PNG 图片

适合想把二维码存成文件、打印出来或者发朋友圈的场景。

先复制你的邀请码：「我的」→「邀请另一半」→ 点一下邀请码区域即可复制。

然后在项目目录里跑：

```bash
npm run qr -- https://xxx.vercel.app/join?code=你的邀请码
```

比如：

```bash
npm run qr -- https://couple-dates-abc.vercel.app/join?code=AB3D7K
```

它会在项目的 `qrcodes/` 目录里生成一张高清 PNG（1024×1024），
同时在终端里打印一个**能直接用手机扫的字符画**，很方便。

### 方法 C：复制邀请链接直接发

1.「我的」→「邀请另一半」→ 点 **复制链接**
2. 直接粘到微信里发给她

### 方法 D：用系统分享面板

「我的」→「邀请另一半」→ 点 **分享给 Ta**，手机会弹出系统分享面板，
可以直接选微信、QQ 等。电脑上不支持时会自动退化成复制。

## 第 9 步：以后怎么更新项目

### 9.1 改代码 → 自动部署

Vercel 已经和你的 GitHub 仓库绑定了。以后只要：

```bash
git add .
git commit -m "改了什么"
git push
```

**Vercel 会自动检测到并重新部署**，一两分钟后线上就更新了。你什么都不用做。

想看看部署进度：Vercel 项目页 → **Deployments** 标签。

### 9.2 数据库结构要改怎么办

**不要**直接改 `0001_init.sql`。正确做法是新增一个迁移文件：

1. 在 `supabase/migrations/` 里新建 `0002_xxx.sql`
2. 写好你的改动（建表 / 加字段 / 改策略）
3. 把它粘到 Supabase 的 **SQL Editor** 里执行一次
4. 把文件提交到 GitHub，这样以后换数据库还能照着重建

### 9.3 部署出问题了想回滚

Vercel 项目页 → **Deployments** → 找到上一个正常的版本 → 右边 **⋯** → **Promote to Production**。

Vercel 会立刻切回那个版本。

### 9.4 换了电脑怎么继续开发

```bash
git clone https://github.com/你的用户名/couple-dates.git
cd couple-dates
npm install
# 重新创建 .env.local，把 Supabase 的 URL 和 key 填进去
npm run dev
```

`.env.local` 不会被提交到 GitHub（这是对的，为了安全），所以新电脑上要手动重建一份。

## 附录 A：常见问题排查

| 现象 | 原因 | 怎么解决 |
| --- | --- | --- |
| 打开只看到「**还差一步：连接数据库**」 | 没配置环境变量 | 检查 `.env.local`（本地）或 Vercel 的 Environment Variables（线上），填好 URL 和 anon key 后**重新部署** |
| 打开只看到「**连接不太顺利**」 | URL / key 填错了，或者项目被暂停 | 核对 Project URL 有没有多余的斜杠或空格；去 Supabase 看看项目是不是被暂停了 |
| 注册后提示「**请先到邮箱里点一下确认链接**」 | 邮箱确认还开着 | 按第 2.4 步关掉 `Confirm email`；或者让她去邮箱点一下链接 |
| 登录提示「**邮箱或密码不正确**」 | 密码输错了，或者之前是用别的邮箱注册的 | 换个密码试试；确认邮箱拼写 |
| 注册提示「**这个邮箱已经注册过了**」 | 同一个邮箱只能注册一次 | 直接切到「登录」标签登录 |
| 部署成功但**页面是演示模式**（顶部有黑条提示） | Vercel 上设了 `NEXT_PUBLIC_DEMO_MODE=1` | 去 Vercel 的 Environment Variables 把这个变量**删掉**，然后 Redeploy |
| 改了环境变量但**没生效** | `NEXT_PUBLIC_*` 是打包时注入的 | 必须在 Vercel 里 **Redeploy** 一次 |
| 「**这个情侣空间已经有两个人啦**」 | 空间满了 | 一个空间就是两个人。如果你是第三个，需要自己新建一个空间 |
| 「**邀请码不对**」 | 邀请码输错了，或者对方重新生成过 | 核对 6 位邀请码；重新生成过的话旧码就失效了，要新的 |
| 两个人**数据不同步** | 网络抖动，或者实时连接断了 | 把页面切到后台再切回来会自动拉最新数据；刷新页面一定是最新的 |
| 女朋友打不开链接 | 手机网络，或者域名拼错 | 让她把链接复制到浏览器直接打开试试 |
| Supabase 显示 **Project paused** | 免费项目连续 7 天没活动被自动暂停 | 在控制台点 **Resume project**，数据不会丢 |

### 怎么确认数据库真的在工作

在 Supabase 左侧点 **Table Editor** → 看 `dates` 表：

- 你在小程序里新建一次约会，这张表里就会多一行
- 没有多 → 说明前端没连上数据库，回去检查环境变量

## 附录 B：不用 GitHub 的部署方式

如果你不想用 GitHub，可以用 Vercel 命令行直接部署：

```bash
# 在项目目录里
npx vercel

# 按提示登录（会打开浏览器）
# 几个问题的回答：
#   Set up and deploy?           → Y
#   Which scope?                 → 选你自己的账号
#   Link to existing project?    → N
#   What's your project's name?  → 回车用默认
#   In which directory is your code located? → 回车（默认 ./）
```

它部署的是**开发版本**。要正式上线：

```bash
npx vercel --prod
```

**注意**：这种方式下环境变量要单独配：

```bash
npx vercel env add NEXT_PUBLIC_SUPABASE_URL
npx vercel env add NEXT_PUBLIC_SUPABASE_ANON_KEY
npx vercel env add NEXT_PUBLIC_SITE_URL
```

每个都会提示你粘贴值、选择环境（选 `Production`、`Preview`、`Development` 都选上）。
配完再 `npx vercel --prod` 一次。

## 附录 C：费用与额度

| 服务 | 免费额度 | 你们会用多少 |
| --- | --- | --- |
| **Vercel Hobby** | 100 GB 流量 / 月 | 两个人用，远远用不完 |
| **Supabase Free** | 500 MB 数据库、5 GB 流量 / 月、50000 月活用户 | 几百次约会大概几百 KB |

**两个需要注意的地方：**

1. **Vercel 的 Hobby 计划只允许个人非商业用途。** 你们两个人自己用完全没问题。
2. **Supabase 免费项目连续 7 天没有数据库活动会被自动暂停。**
   官方文档：https://supabase.com/docs/guides/platform/free-project-pausing
   暂停前一周会给你发邮件提醒；真的被暂停了，在控制台点一下 **Resume project** 就能恢复，
   **数据不会丢**，恢复后一年内都可以还原。
   平时你们隔几天用一次就不会触发。

两个服务的免费额度对「两个人记录约会」这个场景来说绰绰有余，正常情况下**一分钱都不用花**。

## 需要帮助？

程序里有关键的自检命令，改完东西可以随时跑一下：

```bash
npm test             # 一次跑完下面全部（类型 + 逻辑 + 数据库 + 页面渲染）
npm run typecheck    # 类型检查
npm run db:test      # 数据库结构 + 权限隔离（30 项，不需要联网）
npm run logic:test   # 倒计时、统计等逻辑（51 项）
npm run render:test  # 全部页面能不能正常渲染（45 项）
```

如果 `db:test` 全绿，说明数据库这一层是健康的。
